CI/CD

GitHub Actions workflows: .github/workflows/android-v2.yml builds, tests, and packages every push, and .github/workflows/release-v2.yml publishes a release APK on v* tags. Latest status: actions tab.

Triggers

Push toWhat runs
mainbuild-test job (compile + unit tests + APK artifact)
sonder-v2build-test and release job (keystore-signed if secrets present, debug key otherwise)
pull requestsbuild-test job
v* tag, or manual run of release-v2.ymlunit tests, release build, verifier, GitHub Release

Jobs

  • build-test — JDK 17, Gradle wrapper (pinned 9.3.1, SHA-verified), runs assembleDebug + test. Uploads the debug APK as a workflow artifact you can sideload directly.
  • release — assembleRelease. Signed with the keystore when the four secrets are configured, with the Android debug key otherwise — the APK installs for sideloading either way, but a debug-signed one can't be published to Play.
  • release-v2.yml / release — on v* tags or a manual run. Runs the unit tests as a gate, then builds with -Psonder.version.name and -Psonder.version.code (tag without the v, and the workflow run number — a monotonic versionCode lets each release install over the previous one). Verifies the APK's versionName, versionCode, and signer with aapt2 + apksigner before publishing it as sonder-v2-<version>.apk on a GitHub Release with generated release notes.

Release signing secrets

Add these under repo Settings → Secrets and variables → Actions:

SONDER_KEYSTORE_B64        # base64 of your .jks keystore
SONDER_KEYSTORE_PASSWORD   # keystore password
SONDER_KEY_ALIAS           # key alias
SONDER_KEY_PASSWORD        # key password

Generate a keystore locally with:

keytool -genkeypair -v -keystore sonder.jks -keyalg RSA
  -keysize 2048 -validity 10000 -alias sonder

Base64 it for the secret:

base64 -w0 sonder.jks    # Linux/macOS
base64 sonder.jks         # macOS (alternative)
certutil -encode sonder.jks encoded.txt   # Windows

Notes and gotchas

  • The workflow uses bash ./gradlew — Windows git often strips the exec bit, which CI fixed via git update-index --chmod=+x.
  • gradle.properties in the repo deliberately contains no machine-specific org.gradle.java.home — both dev machines and runners supply JAVA_HOME.
  • The release job's trigger is sonder-v2. Since main is now the default branch, tag a release or push to sonder-v2 to produce release APKs.
  • A v* tag fires two workflows: release-v2.yml (this app) and the legacy release.yml (Flutter). They share a concurrency group keyed on the tag, so they queue instead of racing to create the same release.
  • Keystore properties are optional. Without them the release build falls back to the Android debug key, so assembleRelease still produces an installable APK locally and in CI.

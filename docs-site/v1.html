V1 — THE FLUTTER APP

Sonder v1 lives on main's history and in the repo root: a Flutter implementation with native Android enforcement plugins.

Legacy

v1 is preserved but not developed further. Its rules differ from v2 (hard lockout after losses, 20-second revocation, no debt model) — don't apply v2's rules to it or vice versa.

What it did

  • Flutter UI over a Kotlin platform channel: accessibility detection, overlay, and lockout enforcement in native code.
  • Blackjack gate with the same core idea — win to enter — but a simpler economy: each loss added hard lockout time, each win granted a fixed access window.
  • Shorts/Reels surface detection in some OEM builds (see docs/android-enforcement.md).

How v2 differs

Why the rewrite

Flutter's UI costs — the engine's startup latency on a gate that must appear in milliseconds, plus the friction of keeping platform-channel enforcement code and Dart state in sync — pushed v2 native. Compose let the pixel design system (hard frames, stepped shadows, steps() motion) be expressed directly, and the rules engine moved into pure Kotlin where it can be unit-tested without a device.

Enforcement internals Why blackjack?

ACCESS RULES

The complete contract between you and the machine. These rules are implemented in pure Kotlin and enforced by 27 unit tests.

Hand outcomes

ResultEffect
Win+5:00 access to the target app, or −10:00 debt if you owe any
Loss+10:00 lockout debt (capped at 60:00)
PushFree replay — no effect, hand re-dealt

Table rules

  • Single 52-card deck, reshuffled before each hand.
  • Dealer stands on all 17s including soft 17.
  • Blackjack on the deal (natural) = instant win, no play needed.
  • HIT and STAND only — no double, split, or surrender. Deliberately austere.

The debt model

Debt is a negative bank you carry between hands. It exists so that a bad streak is recoverable rather than a wall:

  • Each win while in debt removes 10 minutes.
  • A win at zero debt grants 5 minutes of access.
  • Debt is capped at 60 minutes — further losses change nothing.

Worked example

Three losses, two wins in a row: 10+10+10 = 30:00 debt, then 30−10 = 20:00, then 20−10 = 10:00. You still owe 10 minutes and remain locked out. You'd need one more win to reach 0 and a further win after that to get in — a six-hand session total.

Timers and revocation

All timers are stored as absolute epoch milliseconds, so they survive process death, reboots, and Doze. Revoke also fires if the granted app's window closes for longer than the absence threshold — even with minutes still on the clock.

State machine

            ┌─────────┐   open target    ┌─────────┐
            │  IDLE   │ ───────────────▶ │  GATE   │ (BlockActivity)
            └─────────┘                  └────┬────┘
                 ▲              win     lose  │ keep gambling
                 │ +5min        ┌──────┐ ┌────▼─────┐
                 │              │GRANT │ │  DEBT    │◀───┐
            ┌────┴─────┐        └──┬───┘ └────┬─────┘    │ loss
            │ IN APP   │◀───────────┘          │ walk away│
            │ (timer)  │   absent >60s         ┌──▼──────┐  │
            └──────────┘ ─────────▶IDLE        │ LOCKOUT │──┘
                                               └─────────┘

Any timer expiring or revocation event returns the machine to IDLE; the gate reappears the next time the target is opened. Source of truth: domain/AccessPolicy.kt + domain/BlackjackRules.kt.

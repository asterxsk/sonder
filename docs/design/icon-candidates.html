SONDER / LAUNCHER ICON CANDIDATES

Revision 2. The first five candidates are kept at the bottom of this page and rejected, with reasons — they were all rectangles with something inside them, and a rectangle has no silhouette. These four have one.

MASK GUIDES

The mask buttons apply to every tile at once. Your OnePlus/ColorOS masks to a circle, which is the harshest case — it crops the corners a rectangle needs to be recognisable.

The three tests that killed the first five. Silhouette: flattened to solid black, does the shape still say something? A framed panel becomes a black square. Mask fit: a circle crops corners, so a mark whose identity lives in its corners loses it. One colour: the themed-icon layer is a separate drawable the launcher flattens, so any interior painted with an opaque fill turns into a solid block. Every mark below is checked against all three, and each has a silhouette row and a monochrome row so you can judge it yourself rather than take my word.

HOME SCREEN, AT REAL SIZE

All four at 48dp beside ordinary app tiles, on a dark wallpaper and a pale one. The pale one is the honest test — most people are not running a near-black home screen.

REJECTED — THE FIRST FIVE

Kept here so the reasoning is visible rather than asserted. Every one of these is a frame with an object inside it, which is why they collapse into identical black squares in the silhouette test.

Foreground and background are separate drawables and Android parallaxes them against each other on some launchers, so the mark cannot sit flush to the edge or it shears. Each icon is three files: ic_launcher_background.xml, ic_launcher_foreground.xml, ic_launcher_monochrome.xml — all VectorDrawable, which also retires the quality-pass spec's objection, since that was about a raster icon pipeline rather than vectors.
